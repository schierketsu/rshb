## Суть за 30 секунд

**Проблема.** О сбоях и задержках казначейских операций служба ИТ-мониторинга узнаёт вручную —
от сотрудников бэк-офиса, с задержкой в десятки минут. SLA контролировать трудно, отчётность неполная.

**Решение.** Между системами стоит **Integration Adapter**. Он наблюдает за Treasury.Back, не дорабатывая
её: опрашивает read-only реплику БД и проверяет доступность серверов. Технические признаки проблем
адаптер превращает в **нормализованные события**, привязанные к ИТ-услугам каталога «Диво».
Затем он **надёжно доставляет** их по REST (push, outbox, повторы, идемпотентность). «Диво» группирует
события, создаёт и **автоматически закрывает** инциденты, ведёт SLA и дашборды.

```
Diasoft FA# Treasury.Back ──SQL read-only──▶ Integration Adapter ──HTTPS REST push──▶ API Gateway ──▶ «Диво»
   (без доработок)                          правила · outbox · retry · DLQ          mTLS · OAuth2      события → инцидент → SLA → дашборд
```

**Эффект (цель):** обнаружение сбоя ≤ 2 мин вместо 15–40, ≥ 80 % инцидентов регистрируются автоматически,
100 % сбоев попадают в SLA-отчёт с точной длительностью.

## Ключевые архитектурные решения

1. **Adapter между системами** — Diasoft не знает модель «Диво», «Диво» не знает внутренности Diasoft.
2. **Push по событию + метрики по расписанию + heartbeat** — гибрид под разные задачи.
3. **Transactional outbox + повторы + DLQ** — недоступность «Диво» не теряет ни одного события.
4. **Идемпотентность по `eventId`** — повторная доставка не создаёт второй инцидент.
5. **Событие ≠ инцидент** — группировка по `correlationKey` и пороги, без «шторма» инцидентов.
6. **Пара FIRING / RESOLVED** — инцидент закрывается сам, длительность сбоя для SLA точная.
7. **Heartbeat («dead man's switch»)** — если упал сам адаптер, «Диво» узнает об этом.
8. **Минимизация данных** — суммы, счета и контрагенты не передаются (банковская тайна).

## Как проверить

```bash
# контракт: схема, 14 примеров, OpenAPI
pip install jsonschema pyyaml openapi-spec-validator
python tools/validate.py

# макеты в Figma
#   Figma → Plugins → Development → Import plugin from manifest… → figma-plugin/manifest.json
#   Plugins → Development → «Диво × Diasoft — макеты»

# превью макетов без Figma (нужны Node.js и Chromium; шрифт Onest ставится через npm)
cd tools/figma-preview && npm install && node render.js
```

Спецификацию API удобно смотреть в [Swagger Editor](https://editor.swagger.io): File → Import file → `api/openapi.bundled.yaml`.

## Допущения

* Внутренний API «Диво» публично не описан, поэтому контракт спроектирован как **целевой** для
  интеграционного слоя «Диво Сервис». Известно, что банк интегрирует смежные системы с «Диво» через
  веб-сервисы без их доработки ([ComNews, 2025](https://www.comnews.ru/digital-economy/content/240559/2025-08-06/2025-w32/1012/rosselkhozbank-udivil-hp)).
* Структура БД Treasury.Back закрыта, поэтому Source Connector описан на уровне представлений
  «операции в работе / шаги закрытия дня / журнал ошибок».
* Нормативы, коды услуг, КЕ и SLA — правдоподобные примеры; в проекте их утверждает владелец услуги.
